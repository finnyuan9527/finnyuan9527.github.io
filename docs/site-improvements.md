# 网站内容组织与结构改进记录

日期：2026-09-30。范围：本地站点的首页、栏目、五个案例、三篇文章、关于页与联系页；未发布到线上。

## 判断标准与改动对应

| 评估维度 | 判断标准 | 原有问题 | 已完成调整 |
| --- | --- | --- | --- |
| 信息架构 | 初次访问者能根据名称预测入口内容 | 电影化栏目名称增加理解成本，栏目名称不一致 | 主导航统一为首页、项目案例、思考与观点、关于我、联系；保留视觉风格作为辅助表达 |
| 分类逻辑 | 同层分类采用同一维度，归属明确 | 建设方向与研发效率等用途混在同一层 | 统一为 AI 平台与治理、业务智能化、企业系统与集成；用途采用标签表达 |
| 导航可达性 | 核心页面从任一栏目均可到达 | 联系页缺少主导航入口，移动导航触控区域较小 | 加入联系导航、页脚入口及关键页交流入口；移动端提供菜单按钮，导航与筛选点击区域至少 44px |
| 层级与方向感 | 当前栏目、返回路径和正文结构清楚 | 当前页提示与筛选状态不充分 | 导航增加当前页语义；案例返回保留分类，支持浏览器前进后退；长文章提供章节目录 |
| 核心内容优先级 | 访问者先看到与判断能力相关的内容 | 首页介绍较长，案例出现较晚 | 首页顺序改为定位与入口、精选案例、能力、简介、近期文章、联系；在 1200px 验证视口中案例标题由约 2122px 提前至约 603px |
| 内容证据 | 区分职责、项目阶段、已记录结果与设计目标 | 不同成熟度的项目容易被视为同等交付成果，指标口径不足 | 案例卡增加职责、阶段和结果摘要；详情增加公开证据与口径、方案取舍、适用边界；不推算缺少口径的收益 |
| 内容效率 | 列表支持判断，详情提供新增信息 | 列表与正文重复、页面读完后缺少下一步 | 精简重复介绍；案例正文补充约束与取舍；案例与文章相互关联，并提供其他案例、继续阅读和交流入口 |
| 需求匹配 | 业务负责人能判断价值，技术人员能判断边界，读者能复用方法 | 观点偏抽象，关于页含面向作者的网站规划内容与术语 | 删除关于页的网站规划描述；改写术语；文章补充验证、验收、责任划分和 RAG 评测记录清单 |
| 基础可访问性 | 键盘导航、当前状态、标题与对比度可理解 | 缺少跳到正文和筛选状态语义，铜色正文对比度偏低 | 增加跳到正文、焦点样式、aria-current、aria-pressed、结果播报、单一 H1 与连续标题层级；加深铜色并支持减少动态效果偏好 |
